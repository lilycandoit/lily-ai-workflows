# UI Redesign Workflow

Goal: refresh a screen or product surface with a clearer visual direction while preserving the user flow and business purpose.

Use this when the current interface feels outdated, inconsistent, or visually unclear, and a stronger visual system is needed.

## Read

Read:

1. the page or feature being redesigned
2. its current information hierarchy and user journeys
3. existing design system, tokens, or shared component patterns
4. product requirements, screenshots, or product notes

## Rules

- Preserve the user flow and core functionality.
- Make the hierarchy clearer, not more complex.
- Prefer reusable patterns over one-off styling.
- Keep accessibility, readability, and responsiveness in scope.
- If the redesign is large, split it into staged passes instead of a giant rewrite.
- Do not invent brand strategy unless the user asks for it.

## Execute

1. identify the core problems with the current UI
2. define the design direction, hierarchy, and tone
3. propose a clearer layout and component treatment
4. update spacing, typography, panel treatment, controls, and states
5. keep the implementation consistent with the existing product stack
6. call out anything that should be deferred or rebuilt later

## Output

Return:

- design direction and rationale
- what changed visually
- which structural or stylistic decisions were kept vs changed
- trade-offs or risks
- whether this should be implemented as a polished pass or staged redesign
