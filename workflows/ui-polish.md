# UI Polish Workflow

Goal: make an already-working UI feel more intentional, consistent, and refined without changing the core structure.

Use this when the product flow is correct and the screen only needs visual improvement: spacing, hierarchy, typography, button states, contrast, alignment, and consistency.

## Read

Read:

1. the target screen or component
2. surrounding design system or common patterns
3. current styles, spacing, and component states
4. any user-facing acceptance criteria for the page

## Rules

- Keep the existing information architecture.
- Avoid structural changes unless they are clearly needed for usability.
- Prefer consistency over novelty.
- Maintain accessibility and interaction clarity.
- If the UI needs a broader visual reset, stop and recommend `ui-redesign.md`.

## Execute

1. review the current layout and identify weak spots
2. improve spacing, alignment, hierarchy, and readability
3. tighten typography and button state styling
4. fix inconsistent margins, densities, or visual weight
5. verify the result still matches the product's purpose and flow

## Output

Return:

- what was polished
- files changed
- design decisions made
- any intentional trade-offs
- whether a more substantial redesign is still recommended
